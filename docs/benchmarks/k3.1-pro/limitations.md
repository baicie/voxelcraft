# 已知限制与技术债

本文件记录经实现审查后仍存在的缺口。未完成的项目不能因界面存在而被视为通过。

## 世界、渲染与性能

- 当前网格是“每 Chunk 一次面剔除批处理 + 顶点 AO”，没有实现 Greedy Meshing。对重复地表仍有进一步合并空间。
- 光照使用太阳/半球光与最多 6 个点光源，没有方块光/天空光的逐格传播，也没有跨 Chunk 光照增量。
- 水只有静态水面、透明材质、游泳和溺水，**没有水流传播、源方块、流体更新**。
- 没有天气系统（雨/雪/雷电）或对应环境音。
- 地形生成和 Mesh 共用一个 Worker，新进入世界时最多各 3 个并发任务；需要更细的任务优先级和背压实测。
- 渲染距离 2–6，没有 LOD、远景雾化之外的优化；没有地图/导航。
- 仅用软件 WebGL 做过 20 秒级冒烟，**未执行 5 分钟持续探索和内存曲线**，不能声称长期无内存增长。
- 阴影为单个方向光的 2048 阴影图；为避免地形自阴影条纹，Chunk 地形不投射阴影，仅生物投射，写实性有限。

## 玩法

- 建造、玻璃、楼梯（圆石/木板方块组合）与跨 Chunk 方块保存由同一编辑表支持；但跨 Chunk 建筑、大量快速放置没有专门自动化压力测试。
- 农业只有“种子右键草地 → 耕地 + 小麦方块”的即时简化行为；没有生长阶段、收获循环或熟食农业链。
- 生物 AI 是轻量状态机与直接位移，没有 A* 寻路、群体行为或复杂生成规则。生物物理可能在地形陡峭处卡住。
- 三只/四只生物可观察，但缺乏刷怪上限之外的生态平衡；狼只在受击后近身反击。
- 战斗有距离、伤害、冷却和击退；没有护甲、装备槽、武器耐久 HUD 之外的完整战斗系统。
- 熔炉 UI 采用点击自动转移当前背包原料的方式；没有任意拖拽物品到熔炉槽，也没有经验值。
- 工具等级和熔炼已实现；但**完整真实链路：木镐→石镐→熔炼铁锭→铁镐尚未由 E2E 全流程验证**。
- 没有盔甲、盾牌、弓、附魔、药水等高级装备。
- 世界结构只有地表石砖遗迹和地下发光石房间；没有村庄、废弃矿井或更复杂地牢。
- 创造模式背包是固定初始物品集合，未提供完整创造物品搜索/无限方块面板。

## 交互与 UI

- 背包使用点击拿起/放下与 Shift 快速移动，虽支持整叠、拆分和交换，但**未实现原生拖拽放置或完整鼠标悬浮物品跟随规则**。
- 快捷栏在游戏内不响应直接点击（可用数字键/滚轮）；点击 HUD 槽没有拾取行为。
- UI 文案目前为英文，未提供多语言。
- 设置包含鼠标灵敏度、音量/静音、渲染距离；没有自定义键位。
- 不支持移动端触控或手柄；窄屏 CSS 有基础适配，但未在真实设备验证。
- 有网页可访问性基础（按钮、label、testid），但 Canvas 3D 内容和 HUD 对屏幕阅读器不可用。

## 存档与可靠性

- 保存流程实际通过 IndexedDB 事务和同世界队列；但**未注入 IndexedDB 配额/磁盘故障来验证所有错误分支**。
- 只实现 schema 1 → 2 迁移，后续迁移策略尚未积累。
- 目前保存的是玩家背包、编辑表、熔炉、掉落物与世界时间；生物和作物生长未持久化。
- 自动保存每 30 秒一次，没有版本化快照回滚或云同步。
- 世界列表支持删除/导入/导出和重命名入口尚未实现（README 不应宣称重命名）。
- 没有正式的后端、账号或反作弊。

## 测试覆盖缺口

- 单元测试 24 条，覆盖核心纯逻辑；Three.js 渲染输出、音频、真实 WebGL 资源回收没有单测。
- Playwright 只有 2 条端到端用例；未覆盖死亡与重生、熔炉 UI、工作台 3×3、夜间、跨 Chunk 建筑、浏览器刷新后继续同世界（当前测试通过保存退出→再次进入验证）。
- 没有视觉回归基线、性能断言或内存断言。
- 没有在 Firefox/Safari/低端真机上验证。
- 第三方资源只使用 Three.js/Vite/Vitest/Playwright；程序纹理和音效原创，但音效质量为基础合成音。

## 文档/报告口径

- 性能数字来自软件 WebGL 测试机，不能代表用户桌面显卡。
- 所有标记 NOT RUN 的压力测试与视觉场景均不视为 PASS。
- 综合评分按已提交代码和真实证据给出，不按需求数量自动判满分。

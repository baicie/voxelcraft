## 4. 持久化与迁移

- schema V2：`worlds`、`players`、`chunkDeltas`、`blockEntities`、`entities`、`saveMeta`，保留旧 `chunkEdits`。
- `saveBundle` 在单个 `readwrite` 事务中写入世界、玩家、差异、熔炉、掉落物和保存序号；`deleteMissingForWorld` 清理已删除记录。
- V1 → V2：`schemaVersion=2`、`mode='creative'`、`generatorVersion=1`、`difficulty='peaceful'`、补齐 `lastPlayedAt`、数字 ID → 稳定 ID、支持负坐标与未访问世界。
- V2 玩家背包固定 36 格；选中槽 0–8。
- 旧 `chunkEdits` 只读兼容，不删除。

## 5. 测试加速边界

完整闭环 E2E 为把约 30 分钟压缩到 31 秒，使用仅开发环境可见的测试钩子：

- 确定性传送玩家到资源附近；
- 对部分原木/石头/矿石直接调用生产代码 `breakBlockAt`，仍走工具判定、耐久、掉落与拾取；
- 熔炉用 `FurnaceStore.tick(1850)` 加速，规则/槽位/持久化仍为生产逻辑；
- 工作台/熔炉射线不稳定时用 `useBlockAt` 直达交互路径。

真实鼠标砍树由独立 E2E 覆盖；工作台/熔炉右键打开已人工/脚本验证。正常移动速度下的完整游玩仍需人工确认。

## 6. 未验证/已知限制

- 生命、饥饿、战斗、死亡、生物、流体、多人、LOD、Greedy Meshing 不在 V0.2 范围。
- 未做 >30 分钟内存/GPU 泄漏回归；仅 6 秒稳态与 56 MB 采样。
- V1 迁移使用合成 fixture + fake-indexeddb，未导入真实用户 V0.1 数据库回归。
- 熔炉真实 10 秒/个的等待未在 E2E 完整等待；由单元 tick 测试和加速 E2E 覆盖。
- 背包打开期间自动保存暂停；强制终止浏览器可能丢失界面中尚未放回的物品。
- 未实现按 Q 丢弃、拖拽、配方书、手持模型、方块裂纹 overlay。
- 火把不传播光照。
- 世界删除/重命名/导入导出 UI 未暴露。
